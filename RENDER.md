# Запуск секретаря на Render

Сначала выполните настройку в Telegram из README.md (токен, Business Mode, подключение бота).

## Вариант А. Web Service (в том числе бесплатный) — режим webhook

В этом режиме **Telegram сам присылает сообщения на адрес вашего сервиса**. Бесплатный сервис засыпает без
запросов, но входящее сообщение будит его, поэтому пинговать его не нужно. Платой за бесплатный тариф
будет задержка: если сервис спал, первый ответ придёт примерно через минуту (так Render описывает
пробуждение), потом — сразу.

### 1. Загрузите проект в приватный репозиторий GitHub

```
git init
git add .
git commit -m "Telegram secretary"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/telegram-secretary.git
git push -u origin main
```

Перед этим подставьте в `config.json` реальные цены, адрес и график. Токена в файлах быть не должно —
он вводится только в Render.

### 2. Создайте сервис: New → Web Service

| Поле | Значение |
|---|---|
| Language | Python 3 |
| Branch | main |
| Region | Frankfurt |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python secretary.py` |
| Instance Type | Free |

### 3. Переменные окружения (Environment)

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `MODE` | `webhook` |
| `WEBHOOK_URL` | адрес сервиса с его страницы, например `https://tgbot.onrender.com` (без `/` на конце) |
| `TZ_NAME` | `Asia/Tashkent` |
| `PYTHONUNBUFFERED` | `1` |

`PORT` Render задаёт сам. Адрес сервиса виден вверху страницы сервиса; если задать `WEBHOOK_URL` сразу
не получается (адрес появляется после создания) — создайте сервис, скопируйте адрес и добавьте переменную:
сервис перезапустится.

### 4. Проверка

1. **Logs**: должны появиться строки `Секретарь запущен: @имя_бота, режим webhook…` и
   `Webhook установлен: https://…/tg`.
2. Откройте бота в Telegram, нажмите **Start**, отправьте `/status` — бот ответит состоянием.
3. Отправьте `/on` и напишите вашему аккаунту с другого аккаунта («Salom» или «Сколько стоит?»): клиент
   получит автоответ, а вам в личку придёт уведомление. Затем `/off`.

Если бот пишет, что у него выключен Business Mode — включите его в @BotFather (README, шаг 2).

### Ограничения бесплатного тарифа (по документации Render)

- Файловая система временная: после перезапуска или засыпания бот забывает `/on`, свои тексты (`/text`),
  игнор-лист и паузы между ответами. Расписание (`AWAY_FROM`/`AWAY_TO`) и `config.json` остаются.
  Подключение Business бот при необходимости запрашивает у Telegram заново.
- Render может перезапустить бесплатный сервис в любой момент.
- Лимит — 750 бесплатных часов в месяц на аккаунт.

Для «забывчивости» есть простое решение: пользуйтесь **расписанием** (`AWAY_FROM`/`AWAY_TO`) вместо `/on`.

## Вариант Б. Платный Background Worker + диск — режим polling

Стабильнее и сохраняет настройки: **New → Background Worker**, Build `pip install -r requirements.txt`,
Start `python secretary.py`, переменные `BOT_TOKEN`, `TZ_NAME`, `PYTHONUNBUFFERED=1` (режим `MODE` не задавайте).
Добавьте **Disk** (Mount Path `/data`) и переменную `STATE_FILE=/data/state.json`.
Цена и доступность смотрите на render.com/pricing.

## Как менять настройки потом

| Что | Как |
|---|---|
| «Не в сети», тексты, игнор-лист | команды боту в личку |
| Триггеры и тексты в `config.json` | изменить файл → `git push` → Render сам пересоберёт и перезапустит |
| Расписание, часовой пояс, паузы | сервис → **Environment** → изменить переменные |

## Частые проблемы

- **Бот не отвечает клиентам.** `/status` → «Сейчас не в сети: да?» Проверьте право «Отвечать на сообщения»
  в Настройки → Telegram Business → Чат-боты и что в логах нет ошибок.
- **Уведомления не приходят.** Откройте бота и нажмите Start.
- **Ошибка `Не удалось войти как бот`.** Неверный `BOT_TOKEN`. Новый токен: @BotFather → `/token`.
- **В логах «Для MODE=webhook нужны PORT и WEBHOOK_URL».** Добавьте переменную `WEBHOOK_URL`
  (это Web Service, не Worker).
- **Конфликт 409 в логах.** Бот одновременно запущен ещё где-то (например, у вас на компьютере) — остановите копию.
