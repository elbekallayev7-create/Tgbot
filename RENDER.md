# Деплой автоответчика на Render

Бот запускается на Render как **Background Worker** (процесс без веб-страницы) и работает круглосуточно,
даже когда ваш компьютер выключен.

> **Стоимость.** Background Worker и Persistent Disk на Render платные (бесплатно там только статические сайты).
> Точную цену смотрите на https://render.com/pricing и в окне создания сервиса — до подтверждения Render её покажет.
> Диск нужен только для того, чтобы бот помнил настройки после перезапуска; без него бот тоже работает
> (см. «Без диска» ниже).

## Что понадобится

- аккаунт на https://github.com и на https://render.com;
- `api_id` и `api_hash` с https://my.telegram.org → *API development tools*;
- Python 3.9+ на вашем компьютере (один раз, для получения строки сессии).

---

## Шаг 1. Получить строку сессии (на своём компьютере)

На сервере нельзя ввести код из Telegram, поэтому входим один раз у себя и переносим вход строкой.

```
pip install telethon
python make_session.py
```

Введите `API ID`, `API HASH`, затем номер телефона и код из Telegram (и пароль двухфакторной защиты, если он есть).
Скрипт напечатает длинную строку — это `TG_SESSION_STRING`. Скопируйте её.

> ⚠️ Строка равна полному доступу к вашему Telegram-аккаунту. Никому не отправляйте, не коммитьте в GitHub.
> **Не запускайте бота у себя с этой же строкой, пока он работает на Render**: Telegram не любит одну сессию
> с двух адресов и может её сбросить (тогда нужно заново сделать шаг 1).

## Шаг 2. Загрузить проект в приватный репозиторий GitHub

1. Создайте на GitHub **приватный** репозиторий (Private), например `telegram-autoreply`.
2. Распакуйте архив и в папке проекта выполните:

```
git init
git add .
git commit -m "Telegram autoreply"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/telegram-autoreply.git
git push -u origin main
```

Файл `.gitignore` уже исключает `*.session`, `state.json` и `.env`. Перед `git push` убедитесь, что
строки сессии нигде в файлах нет.

Перед загрузкой откройте `config.json` и подставьте свои реальные цены, адрес и график: бот отправит
ровно то, что там написано.

## Шаг 3. Создать сервис на Render (через Blueprint)

1. На https://dashboard.render.com нажмите **New → Blueprint**.
2. Подключите GitHub и выберите репозиторий. Render найдёт `render.yaml`.
3. Render попросит значения переменных:

| Переменная | Что вписать |
|---|---|
| `TG_API_ID` | число с my.telegram.org |
| `TG_API_HASH` | строка с my.telegram.org |
| `TG_SESSION_STRING` | строка из шага 1 |

4. Проверьте план и цену, затем подтвердите (**Apply / Deploy**). Render соберёт проект и запустит бота.

Часовой пояс (`Asia/Tashkent`), путь к состоянию (`/data/state.json`) и диск на 1 ГБ уже прописаны в `render.yaml`.
Расписание «не в сети» можно включить, раскомментировав `AWAY_FROM` и `AWAY_TO` в `render.yaml`
(или добавив эти переменные в настройках сервиса: *Environment*).

### Если Blueprint не подходит — вручную

**New → Background Worker** → выберите репозиторий и заполните:

- Language: **Python 3**
- Build Command: `pip install -r requirements.txt`
- Start Command: `python autoreply.py`
- Environment: `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING`, `TZ_NAME=Asia/Tashkent`, `PYTHONUNBUFFERED=1`
- (по желанию) **Disks → Add Disk**: Mount Path `/data`, размер 1 GB, и переменная `STATE_FILE=/data/state.json`

## Шаг 4. Проверить, что работает

1. Откройте сервис → **Logs**. Должна появиться строка вида:
   `Автоответчик запущен для ваш_ник. Триггеров: 5. Состояние: /data/state.json`
2. Отправьте себе в «Избранное» `/away status` — бот ответит состоянием.
3. Включите `/away on` и напишите вашему аккаунту с **другого** аккаунта (например, «Salom» или «Сколько стоит?») —
   должен прийти автоответ. Затем `/away off`.

Если в логах ошибка `TG_SESSION_STRING недействителен` — повторите шаг 1 и обновите переменную в
**Environment**.

## Как менять настройки потом

| Что | Как |
|---|---|
| Включить/выключить, текст, игнор-лист | команды в «Избранное»: `/away on`, `/away text ru …`, `/away ignore @user` |
| Триггеры и тексты в `config.json` | изменить файл → `git push` → Render сам пересоберёт и перезапустит (автодеплой) |
| Расписание, часовой пояс, паузы | сервис → **Environment** → изменить переменные (сервис перезапустится) |

На сервере команда `/away reload` не нужна: изменения `config.json` попадают на Render только через деплой.

## Без диска

Диск можно не брать: удалите блок `disk:` и строку `STATE_FILE` из `render.yaml` (или не добавляйте диск
при ручной настройке). Бот будет работать, но после каждого перезапуска или деплоя забывать:
`/away on`, свои тексты, игнор-лист и паузы (он может повторно ответить тем, кому недавно отвечал).
Расписание и `config.json` это не затрагивает.

Диск полезен ещё одним: по документации Render, при подключённом диске старая копия сервиса останавливается
**до** запуска новой. Это защищает от ситуации, когда две копии бота одновременно используют одну сессию Telegram.

## Частые проблемы

- **Бот не отвечает.** Проверьте `/away status`: включён ли режим вручную или расписание. Помните, что бот
  отвечает только в личных чатах и только на сообщения других людей (не на ваши).
- **Сессия слетела (`AuthKeyDuplicated`, `недействителен`).** Скорее всего, одну строку использовали в двух местах.
  Сделайте новую (шаг 1), обновите `TG_SESSION_STRING`, и не запускайте бота локально с ней параллельно.
- **Сбой на сборке `pip install`.** Версия Python зафиксирована файлом `.python-version` (3.12).
  Не удаляйте его.
- **Нужен перезапуск.** Сервис → **Manual Deploy → Restart / Deploy latest commit**.
- **Хочу остановить бота.** Сервис → **Suspend** (или удалите сервис).
